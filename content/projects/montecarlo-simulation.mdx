# Monte Carlo Simulation Engine

A multi-threaded C++17 quantitative finance engine that prices options and measures portfolio risk using Monte Carlo methods. It implements five stochastic models (GBM, Heston, Merton jump-diffusion, CIR, and correlated multi-asset GBM), four variance-reduction techniques, and a full statistics/risk suite (VaR, CVaR, Sharpe, Sortino, bootstrap confidence intervals). Every run also renders an interactive HTML report with charts of the simulated paths, payoff distributions, and convergence behavior.

[Github](https://github.com/Siddhant-sarkar/Montecarlo-Simulation)

On an 8-core machine it simulates the 10M-path European call in ~75ms (~130M paths/sec) and runs the full 8-part suite — roughly 34M simulated paths across all models — in about 33 seconds.

---

## Features

**Stochastic models**

- Geometric Brownian Motion (GBM) with exact log-normal sampling
- Heston stochastic volatility, via the Broadie-Kaya quadratic-exponential (QE) scheme
- Merton jump-diffusion (log-normal jumps on top of GBM)
- Cox-Ingersoll-Ross (CIR) mean-reverting short-rate model
- Correlated multi-asset GBM via Cholesky decomposition, for portfolio simulation
- Closed-form Black-Scholes pricing and Greeks (delta, gamma, vega, theta, rho) as a validation baseline

**Payoffs priced**

- European calls/puts
- Arithmetic Asian calls (with a geometric-Asian control variate)
- Up-and-out calls and down-and-out puts (barrier options)
- Lookback and digital options

**Variance reduction** (compared head-to-head in one run)

- Plain Monte Carlo (baseline)
- Antithetic variates
- Quasi-Monte Carlo via a Halton low-discrepancy sequence
- Control variates (analytic Black-Scholes / geometric-Asian control)

**Risk & statistics**

- Mean, standard error, percentiles, and 95% confidence intervals
- Value-at-Risk and Conditional VaR (95% / 99%)
- Annualized Sharpe and Sortino ratios
- Bootstrap confidence intervals
- Convergence analysis (running mean vs. path count)
- VaR term structure (scaled across multiple holding-period horizons)

**Engine internals**

- Xoshiro256++ PRNG with per-thread jump-ahead streams for reproducible parallel runs
- Acklam's rational approximation for the inverse normal CDF (used by the Halton/QMC path)
- Work is sharded across `std::thread::hardware_concurrency()` threads with no locking on the hot path
- Self-contained HTML report generator with embedded interactive charts — no external services or JS build step

## How it works

Each simulation shards its path count evenly across the machine's hardware threads. Every worker thread seeds its own Xoshiro256++ generator and calls `long_jump()` a number of times equal to its thread index, giving each thread a statistically independent, non-overlapping random stream — so results are reproducible and don't depend on thread scheduling. Path generation, payoff evaluation, and discounting all happen inline in the worker lambda with no locking, which is what gets the GBM European-call simulation to ~130M paths/sec on 8 cores.

The Heston paths use the Broadie-Kaya QE scheme to sample the variance process without the negative-variance issues of a naive Euler discretization. The CIR short-rate model uses a similar reflection/absorption scheme to stay non-negative. The 10-asset portfolio simulation draws correlated normals via a Cholesky factorization of the target correlation matrix.

## Building it

Requires a C++17 compiler (`g++` or `clang++`) and `make`. On macOS, OpenMP is optional — the Makefile auto-detects `libomp` via `pkg-config` if installed, but parallelism comes from `std::thread`, so the engine runs fine without it.

```bash
cd montecarlo
make            # builds ./montecarlo
make run        # builds, then runs the full simulation suite
make report     # runs, then opens report.html in your browser
```
